# How to change Flavourly safely

## Ground rules

1. **Never rewrite published git history** (no force-push, rebase, amend or squash of pushed commits). Lovable syncs from this repository and would lose history. Fix mistakes with a new commit or `git revert`.
2. **Every commit pushed to `main` is live.** Work on a branch, open a pull request, merge only when CI is green.
3. **One concern per commit.** It keeps reverts clean.

## Before every merge

```sh
bun install --frozen-lockfile
bun run typecheck
bunx eslint . --rule 'prettier/prettier: off'
bunx vitest run
bun run build
```
If you touched `supabase/migrations/`: also run `scripts/replay-migrations.sh` against an empty scratch Postgres (CI does this too). If you changed prices, plan limits or billing: re-run the PayFast sandbox flow in `ACCEPTANCE_SCRIPT.md`.

## Do not hand-edit

- `src/integrations/supabase/*` (generated; `types.ts` is regenerated by Lovable after migrations; `cron-auth.ts` is generated)
- `src/routeTree.gen.ts` (regenerated by the build; commit the result)
- Any migration file that has already been applied. Add a **new** migration instead. The seven no-op duplicate migrations must stay (they keep migration versions in sync).

## Rules the tests enforce (so changes fail loudly)

| If you... | A test will fail unless you... |
|---|---|
| Add a server function | Authorise the tenant (`authorizeTenant`) with the right role, and list it in the role matrix if it is sensitive |
| Read a new environment variable | Add it to `.env.example` |
| Add a migration | Make it replay cleanly on an empty database, enable RLS on every new table, and not duplicate another migration |
| Edit `bun.lock` | Keep it on `registry.npmjs.org` and keep a single lockfile |
| Commit credentials | Remove them (and rotate them) |

## Security habits

- Browsers never get the service-role key. All database access is in `*.server.ts` files called from server functions.
- Never accept identity, tenant or WhatsApp account from the browser without checking it server-side. Use `actorId()` for "who did this".
- Outbound WhatsApp: use `sendWhatsApp()` (billing/quota) or the outbox (opt-out, quiet hours). Never call the operator directly.
- Adding a tenant-scoped query? Always filter by `tenant_id`.

## Releasing

1. Merge to `main`, wait for CI and the Lovable deploy.
2. Open `/api/public/health` and confirm `ok`.
3. Run the quick smoke part of `ACCEPTANCE_SCRIPT.md` (steps 2 and 7).
4. If it is wrong: `git revert` the merge commit and push (a new commit, not a rewrite).
